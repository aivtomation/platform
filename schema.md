# AIVTOMATION.COM - Schema

Цей файл описує правила та конвенції щодо оновлення "Пам'яті" (LLM Wiki) для екосистеми aivtomation.

## Правила
1. **Оновлення логу:** Всі ключові етапи розробки (наприклад, "Розгорнуто телесуфлер", "Додано голосове управління") повинні записуватись у `log.md` з відповідною датою. Формат: `## [YYYY-MM-DD] тип_дії | Короткий опис`.
2. **Структура індексу:** Файл `index.md` завжди повинен містити актуальний перелік існуючих проектів, їх статус та посилання на відповідні папки.
3. **Мова та тон:** Всі технічні коментарі та огляди у вікі ведуться українською мовою. Код (класи, id, змінні) пишуться англійською.
4. **Управління:** AI (Агент) відповідає за синхронізацію та підтримку цих файлів у актуальному стані в процесі роботи.

## Бізнес-Архітектура (AI Automation Agency)
Ці принципи використовуються при розробці нових продуктів та сервісів в екосистемі:
1. **Productized Services:** Платформа розробляє не абстрактні ШІ-рішення, а запаковані, вузьконішеві послуги (наприклад, Агент-Аналітик, Телесуфлер, Агент-Агрегатор) з чітким бізнес-результатом.
2. **Spec-First підхід:** Розробка будь-якого агента починається зі специфікації (System Prompts, Tools) перед написанням коду або налаштуванням платформи.
3. **Evals (Тестування):** Кожен агент проходить автоматизоване тестування (LLM-as-a-Judge) перед розгортанням у продакшені для мінімізації галюцинацій.
4. **HITL (Human-in-the-Loop):** Критичні рішення агентів (публікації, фінансові розрахунки) потребують підтвердження людиною.
5. **Modern Stack:** Пріоритет надається готовим платформам (n8n, Dify, LangGraph) або Headless-рішенням (інтеграції через API в Telegram/CRM), замість кастомного коду з нуля.
6. **Модель монетизації:** 
   - *Setup Fee* за інтеграцію і налаштування (BYOK - Bring Your Own Key).
   - *Monthly Retainer* за моніторинг (Observability) та підтримку.
